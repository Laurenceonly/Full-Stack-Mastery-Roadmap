# Continuing work

Read `RESUME.md` for the latest work log, checks, limitations, branch context, and next task. Read `KNOWLEDGE.md` for the project overview and `ARCHITECTURE_AND_PROJECT_PLAN.md` for requirements. Inspect the actual Git state before making changes; the log is a handoff, not a substitute for verification.

At the end of each work session, update `RESUME.md` with what changed, checks actually run and their results, unfinished work, and a concrete next step. Keep earlier dated log entries. Update `KNOWLEDGE.md` when the product scope or architecture changes. Never record credentials or private user data in these files.

Preserve stable topic IDs and existing saved progress. Keep content, domain calculations, graph adaptation, and UI separate. Keep V2 client-first. Unknown resource access/certificate claims must remain unknown until verified.

Use Node.js 24 LTS. Run `npm test`, `npm run lint`, and `npm run build` for catalog or domain changes. On Windows PowerShell, use `npm.cmd` when `npm.ps1` is blocked by execution policy. Explain commands before asking the learner to execute them.
